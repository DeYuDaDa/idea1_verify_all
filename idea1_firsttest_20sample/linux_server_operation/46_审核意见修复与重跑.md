## 本轮如何调整

1. 先做有界库存调查，最多检查30个厨房场景，保留每个房间的真实物品清单。满足物品数量只是选房条件，不等于放置和机制已经验证。如果仍找不到两只杯子或两只盘子，会明确报告，不能承诺全部20题都能生成。
2. 走近物品、转身和调整俯仰都使用原生小动作，默认移动最多0.1米、转身最多10度、俯仰最多5度，每个动作都采集。公开历史不用瞬移，目标事件前的移动必须在状态比较的边界之外完成。
3. 正式视觉输入只保留第一人称。公开初态会安排身份巡视，用实际第一人称图片建立每个别名的对应；不会用第三方相机画面替代模型没有看到的身份线索。
4. 调试保留第一人称、远景及必要局部视角。相同原生步骤的画面排在同一时间点；只有所有视角都连续相同时才合并。任一视角变化，就保留该时刻全部视角。
5. S 是“给定准确状态与事件”的文字诊断，本来就没有公开图片；页面需要明确用途、场景、状态、事件和问题，并能定位对应V题。私有画面是调试材料，不能补进S的模型输入。

拿起、放下等操作本身仍可能是模拟器一次返回的离散变化。本轮不会生成假中间帧，也不声称取得了Unity每个渲染帧的视频。改善的是原生行走、朝向变化的连续性，以及多视角显示的时间对应。

## 运行方法

同步本轮全部新增和修改文件后，先跑8个代表性构造：H01-1、H02-1、H03-1、H04全部4题，以及H05-1。

```bash
source "$HOME/.config/thor20/server.env"
cd "$HOME/idea1_verify_all/idea1_firsttest_20sample"
bash linux_server_operation/45_repair_hard_capture.sh
```

第45步复用第43步的检查、生成与打包，所以最终ZIP和日志文件名仍以第43步为准。库存调查会增加一些启动时间；它会打印当前检查的房间及已经找到的匹配，不调用模型。新版仍保留失败诊断，不能只看有没有ZIP判断成功。

只验证嵌套组和视角，可用：

```bash
bash linux_server_operation/45_repair_hard_capture.sh --cases H04-1,H04-2,H04-3,H04-4 --scene-limit 3
```

确认代表性样本后再运行全量：

```bash
bash linux_server_operation/45_repair_hard_capture.sh --all
```

ZIP中应检查：`dataset/inventory_survey.json` 的场景选择；`dataset/audit_traces/<题号>/native_result.json` 的动作结果；`review_timeline.json` 的对齐画面；`data/input/*_V.json` 的 `frames` 只能是 `view_id=agent`。用更新后的一键网页审核重新打开新ZIP，旧审核结果不会被覆盖。
