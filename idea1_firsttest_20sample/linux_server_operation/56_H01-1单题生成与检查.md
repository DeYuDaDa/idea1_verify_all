## 这次具体会做什么

1. 保留原有的双杯库存准备和机器槽位校准，确保两杯都能放入机器并真正取回。
2. 绑定真实水龙头与水槽。分别为两杯验证原生开水接水路径、离水保水、真实倾倒、反向旋转扶正并归位，不再重复关水进入/退出对照。接水位置候选来自当前物体的 AABB，位移使用碰撞检查的 MoveHeldObject，单步不超过4厘米；最多五个几何候选，不通过就停止。
3. 恢复初态后开始正式历史：A接水、B接水、倒A、倒B、B再接水。身份按正式历史首次拿起的顺序建立，私有校准不算。正式历史不调用 FillObjectWithLiquid/EmptyLiquidFromObject，不传送杯子。
4. 开机，拿起空A，真实放入机器，沿用预先确定的 Pass 0/Pass 4 观察窗口。核对 A咖啡/B水、位置与设备状态；不延长窗口补结果。
5. 每个检查点持久化期望、实际、回执及图片引用。任何关键节点失败都保留诊断，后续标记未执行，不发布一个“看起来完成”的正式题。

## 结果在哪里，怎么审核

路径由现有 server.env 的 DATA_ROOT 决定，通常位于 `/home/mdy/experiment_data/idea1_firsttest_20sample`。终端末尾打印本次数据目录、ZIP 和日志；不要用旧目录覆盖新记录。

ZIP 中的重要文件：

- `dataset/generation_summary.json`：只应请求 H01-1。构造成功仍为候选、需人工审核；失败为 source_incomplete。
- `dataset/audit_traces/H01-1/h01_checkpoints.json`：C01–C04、T01–T09及接水/倾倒子检查点、私有路径对照与错误记录。始终保留未执行节点。
- `dataset/audit_traces/H01-1/review_timeline.json`：网页用的原生图片时间线、检查点和精确帧映射。
- `dataset/audit_traces/H01-1/native_result.json`：真实原生结果与上下文。

把 ZIP 下载后，使用更新后的 `一键网页审核.bat` 生成一个新的审核网页。网页增加“程序检查点与对应图片（私有审核）”，在模型图片下方也标出对应检查点；这些仅在审核页面显示，不改模型原图、输入文本或隐藏答案边界。检查点会映射到精确全局步骤；完全重复图片可共用文件，但不丢检查点。失败题的诊断页面也有此面板。

人工重点看：首次拿起A和B是否清楚；接水前杯为空、杯子真实到流水下、接水后液面可辨；倒水时同一杯确实转动并清空；另一杯始终保留；最终A放入机器。程序状态通过不等于这些画面已经通过。

若失败，不必重跑全量，把第56步日志与 ZIP 返回即可。尤其不能把“水龙头已开、杯子在水槽附近”代替自然接水成功；当前几何候选和杯口视角仍需要真实运行来验证。
