# H01-1 停在水龙头前：原因与本轮修复

核查包：`20261029T071136Z_hard_groups_20261029T071136Z_LB9vYg_43_hard_groups.zip`。

本轮只有 H01-1；C01、C02通过，C03-A失败。没有正式题发布，没有运行模型。用户看到的“拿A放机器再取回、拿B放机器再取回、拿A走到水龙头前”是私有可行性校准；正式装水历史尚未开始。

## 为什么连水龙头也没开

检查点里五个候选的实际错误都是 `Water target beyond bounded hand reach`。手持杯中心为 `(-1.04459, 1.34330, -1.71392)`；五个目标与它的直线距离约0.96–1.11米，全超过代码设置的0.85米手部位移预算。

原导航的完成条件是水龙头已可见、原生距离不超过1.45米。本次在agent位置 `(-0.75, 0.901, -1.75)` 就完成导航，但这不保证杯子能在0.85米预算内到达水流位置。五次尝试都在调用 MoveHeldObject 前被本地几何检查拦截，C03-A里也没有 ToggleObjectOn，所以本次尚未实际测试流水能否装水，不能据此说自然接水机制失败。

本批次原生 GetReachablePositions 已记录更近的位置，例如 `(-1.25, 0.901, -1.50)`，到第一个接水候选的水平距离约0.73米。这只是可选站位证据，持杯走过去以及之后接水仍需新运行验证。

## 修改了什么

仅在H01-1新增接水专用站位选择：普通导航看见龙头后，还要根据杯子实际中心与接水目标的距离判断是否够近。如果不够近，读取真实可达点，沿原有网格路线和小步 MoveAhead 走近，再重新瞄准并检查实际手部距离。候选站位最多四个，不能用传送替代走路。

仍保留原来的0.85米手部预算、4厘米手部步长、原生碰撞检查和“不直接填水”的约束。私有校准保存最终实际站位，三次正式接水复用对应杯子已验证的站位；不会只因龙头已经出现在画面里就结束接近。

记录新增接近前后的agent位置、手部距离和走路路线；若依然失败，检查点保留具体原生回执、状态和候选错误，校准状态明确为failed，不再停留在searching。

## 图片里的白色“手”

已查看C03-A拿起A后的原始PNG。杯子后方台面上的白色手形物体，对应原生 `objectType=Statue`，ID `Statue|+00.45|+00.91|-02.33`。它是房间里的雕塑摆件，不是agent手部模型。使用同帧相机参数投影其AABB，屏幕范围约x244–366、y217–322，与该摆件所在区域相符；AABB投影是区域核对，不是像素级实例分割。
