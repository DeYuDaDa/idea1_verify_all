# H01-1：自然接水与杯子称呼的修订

本文件修订第54份方案的装水方式与两杯称呼。用户已认可原来的历史顺序和目标事件，本轮不改这些安排，也不改生成代码、不启动模拟器。

## 结论和依据

AI2-THOR 支持“打开水龙头，将空 Mug 移到流水下，自动接水”。正式历史不再采用直接调用 FillObjectWithLiquid 的方案。

已读的具体依据：

- 用户保存的官方物品表 `主线1/AI2THOR文档/object.md:61`：Faucet 可用 ToggleObjectOn 开启，开启后从龙头口产生流水。
- 同表第83行：空 Mug 移到流水下会自动装水；Mug 也可在开启的咖啡机中自动装咖啡，故无需换成别的容器类型。
- 当前 Unity commit `f0825767cd50d69f666c7f282e54abfe58f1e917` 的 `Fill.cs:113`：OnTriggerStay 检查空杯与带 Liquid 标签的触发体接触，然后调用 FillObject("water")。这条调用发生在模拟器接触机制内部，不是生成脚本直接给杯子写水。
- 同构建 `PhysicsRemoteFPSAgentController.cs:2777` 的 MoveHeldObject 支持按相机方向小步移动手持物，可用于靠近流水，但碰撞和可达性仍需当前场景实跑。

这确认了原生机制存在，没有证明当前房间、当前两只杯子的接水路径已经跑通。杯子属于 SinkBasin、Faucet 的 isToggled=true，都不能单独证明接触流水。项目已有水源探测代码也明确保留了这一界限。

## 三次接水都这样做

T01、T02、T05 的目标杯依次为 A、B、B。每次执行以下流程：

| 子步骤 | 实际动作与图片 | 程序检查 |
|---|---|---|
| W01：拿起空杯 | 展示目标杯为空，真实拿起，保持直立。 | 实际拿到的 ID 正确；目标杯未装液体；另一杯在自己的停放位；M 和水龙头关闭。 |
| W02：接近水源 | 持杯走到水槽旁，杯子停在预先校准的流水范围之外；保存接水前图。 | 杯子仍在手中、直立且为空；没有因导航提前装水。 |
| W03：开水 | 打开水龙头，保存流水与旁边空杯的画面。 | ToggleObjectOn 成功且 isToggled=true；杯子此刻仍空。若已经变水，就说明预定的接水边界有误，不能把本帧标成空杯。 |
| W04：接水 | 使用真实 agent/MoveHeldObject 小步将同一杯移到流水下，保留每步返回图片。 | 在预先设定的有界窗口内，同一杯实际发生 isFilledWithLiquid=false→true、fillLiquid=water；不调用 FillObjectWithLiquid 兜底。保存位姿、动作、水源状态和真实变化，不虚构“流水已接触”的原生回执。 |
| W05：移离关水 | 把杯子移离流水，关闭水龙头，展示杯内水面。 | 关水成功且 isToggled=false；杯子仍为水，未因倾斜洒空。 |
| W06：归位 | 把杯子放回自己的停放位，展示归位结果。 | 手中为空；该杯仍有水；另一杯液体与停放关系保持；M、水龙头关闭。 |

三个阶段结束时的状态不变：T01 后 A水/B空；T02 后 A水/B水；T05 后 A空/B水。

两次倒水仍按第54份方案使用真实手持倾斜。必须先确认水龙头关闭，在流水作用范围之外倒水，避免刚倒空又自动装水。

## 正式历史前要多验证什么

共同安排新增水龙头、对应水槽和安全接水路径。两只杯子都要分别验证：

1. 水源关闭时走过同一接水路径，杯子仍空。
2. 水源开启时走过路径，杯子自然装水。
3. 带水移离、关水、回到停放位后，水仍保留。
4. 杯子实际接近流水时，第一视角能看到杯子、流水和它们的位置关系，接水前后能检查杯口。

校准结束恢复两杯均空、各自归位、M和水龙头均关闭、手中为空，之后才开始公开历史。接水可能同时清洁杯子，额外属性变化如实记录，不把它混入本题液体及位置的预期。

若手持路径因水槽边缘或碰撞失败，保留失败，不自动改成直接填水。可以单独验证备选：“关水时把杯子放在流水下→开水→接水→关水→取走”。但 PutObject 到 SinkBasin 不保证落点就在流水下，因此备选也必须实际验证，不能只读承载关系就宣布成功。

流水自动填水是离散的状态变化，不保证模拟连续上涨的水位。网页审核需要看见水源、接水动作和前后液面，而不要求生成模拟器没有提供的水位动画。

## 两只同款杯子怎样命名

接受用户对现有序列可区分性的判断，不再把颜色差异作为本题门槛。命名规则为：

> 在正式历史中，把第一次被拿起来接水的杯子记为 A；把随后第一次被拿起来接水的另一只杯子记为 B。后续再次拿取时，仍沿用这两个身份。

私有校准拿取不计入，初态巡视只看不拿。实际 ID 在程序中固定绑定，并在两次首次 PickupObject 处核对。

模型文本用完整规则建立身份；提问可写“A（正式历史中最先拿起的杯子）现在装什么？”和“B（随后拿起的另一只杯子）现在装什么？”。不能仅写“先拿的杯子/后拿的杯子”而不说明是第一次，因为后面会重复拿取。

网页将“首次拿起 A”“首次拿起 B”对应到实际图片，并分别显示检查点。初态时 A/B 同款不再要求颜色区分；两杯已经建立身份后的连续追踪仍由实际画面审核，不追加隐藏 ID 逐帧跟踪提示。

## 网页检查点和实施边界

第54份方案的 C01–C04、T01–T09 编号保留；三次接水各增加 W01–W06 子检查点，例如 `T02-W04：B 在流水下接水`。

网页将实际图片与这些节点关联，关键帧不受普通导航的 debug 抽样影响。程序状态检查、图片文件完整性、人工视觉判定分别显示。私有程序检查及答案不加入模型输入。

本轮完成的是源码核查和方案修订；没有修改生成器，没有执行 Linux 命令。下一步只实现 H01-1 的自然接水、真实倾倒与逐节点审核，不同时改其他题。
