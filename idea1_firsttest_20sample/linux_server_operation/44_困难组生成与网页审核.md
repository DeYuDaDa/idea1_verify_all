## 第一步：同步代码后，先生成一题

```bash
source "$HOME/.config/thor20/server.env"
cd "$HOME/idea1_verify_all/idea1_firsttest_20sample"
bash linux_server_operation/43_generate_hard_groups.sh
```

默认只尝试 **H05-1**。脚本先运行新增的 mock 测试及相关旧接口测试，测试通过才加载已有Unity构建。接着搭建一题、配置固定相机、记录每次原生动作返回画面和完整metadata，再导出 V/S 两份待发送输入并打包。

先用这一题检查新主机上的“逐步第三方画面→去重→动作边界→网页”链路，而不是一开始把20种构造都跑一遍。原生物品、摆放或取景不满足时，保留失败记录；测试过不代表场景一定成功。

终端会打印数据目录、ZIP和日志，均在 `$DATA_ROOT`，不会写进Git。把新 ZIP 与第43步日志放回 Windows 的 operation_data。

## 第二步：用现有按钮人工审核

双击项目内的 `一键网页审核.bat`，输入刚下载的 ZIP。它会找到包内 `dataset`，输出到新目录，不覆盖旧审核结果。

若需要用命令启动，相同操作为：

```powershell
& 'F:\md\Academic\ICML2026 paper\主线1\idea1_verify_all\idea1_firsttest_20sample\一键网页审核.bat'
```

网页中 V 是完整视觉历史、规则和必要初态说明；S 是准确事件前状态加最后事件，有意没有公开图片。它们是同一物理案例的两种输入版本，不是两次独立模拟实验。两者都是 `prepared_not_sent`，没有模型回答。

公开图片保留每个阶段的帧顺序、重复张数和步骤范围；完整动作、失败回执和原生过程在折叠的私有审计区。目标事件前后的图即使一样，边界也保留。初态像素框只用于把A/B或P/Q的身份与图片对应，不提供后续位置或属性。

如果默认一题没有成功，ZIP仍保存失败原因与现有画面，可以生成诊断网页。请不要重装环境或直接启用全量，把日志和ZIP返回定位即可。

## 第三步：采集链正常后生成其它题

```bash
source "$HOME/.config/thor20/server.env"

```

只选择几题：

```bash

cd "$HOME/idea1_verify_all/idea1_firsttest_20sample"
bash linux_server_operation/43_generate_hard_groups.sh --cases H01-1,H02-1,H03-1,H04-2
```

每次都新建批次，失败不会冒充答案，也不会覆盖上一次。H01需要两只实际可用Mug；H02需要两只Plate与可周转的稳定位置；H04-4仍是待验证的原生改接，失败不算搬运机制反例。默认实现会诚实暴露库存或放置不足，不克隆对象、不在公开历史中瞬移。

`--all`可能返回状态2，表示部分构造未发布；先看 `generation_summary.json` 与诊断网页，不能只看退出码就认为整个环境坏了。一次真正成功的案例最多输出 V/S 两条输入，因此20案例最多40条输入记录。

## 当前实现边界

本次只做了源码静态审查，所有测试和实际场景仍以第43步服务器输出为准。固定视角mask覆盖是取景筛查，不证明液体、温度等语义可读；画面相同也不是相机坏了的充分证据。

新输入使用冻结的 `prepared_requests`，网页按同一份完整文本显示；旧 Qwen 推理脚本会明确拒绝这一新协议，防止它按旧字段白名单丢掉历史或状态。以后接模型时应读取冻结输入，不能把新题直接塞进旧入口。
