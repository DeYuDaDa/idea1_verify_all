### 2026-10-27：ZIP无图，修复实际启动平台选择

已核查 `20261027T080534Z_...wBdhna_43_hard_groups.zip` 和 `20261027T081024Z_...iTGHzq_43_hard_groups.zip`：两个包都只有23个文件、0张图片、0条公开输入。单题 H05-1 和全量首题 H01-1 均在 Controller 构造期间失败，报 `TypeError: expected str, bytes or os.PathLike object, not NoneType`。全量剩余19题没有执行。这是上游采集未开始（`source_incomplete`），并非打包或网页漏图。

AI2-THOR 5.0.0 收到显式 `local_executable_path` 时走 `ExternalBuild`，在 Linux 上将实际构建平台设为 Linux64，忽略请求的 CloudRendering。Linux64 启动可产生 `DISPLAY=None`，随后 Popen 在编码环境变量时失败。原生成入口虽然验证了正确的 CloudRendering 可执行文件，却又显式传入路径，触发了这个分支。

已改成先核对固定缓存中的可执行文件及非空 Data 目录，再只传缓存根目录、固定 commit 和 CloudRendering 平台，让 AI2-THOR 选择已有构建。不会设置虚构 DISPLAY、重装环境或修改系统驱动。CloudRendering 如果显式指定了固定缓存之外的路径，会明确拒绝，避免再次误选 ExternalBuild；Linux64 显式路径行为不变。新增3项无模拟器测试覆盖这些分支。终端和ZIP清单也会输出图片数、发布题目数及失败状态，0图会明确提示“仅诊断包”。
