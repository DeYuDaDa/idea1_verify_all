# 下一步只验证一个原生机制

目的不是把45种设计做成数据集，也不要求全部跑通。已有充分证据的条件保留结论；
只有影响结论的缺口才补实验。新实验按对象、关系、事件和条件解释，不能推广为普遍规律。

第39步已定位：第一次阻断发生在 `PausePhysicsAutoSim`，还没有 Add/Update 相机。
Fork、Ladle、Spatula、Tomato 的 `isMoving` 从 true 变 false；原始元数据没有其它对象字段变化。
Unpause后另有微小位置/角度变化，仍保留检查，不把它们统一当成无影响。

源码修订：暂停/恢复控制阶段单独记录运动标记；暂停后以暂停态为相机检查基准。
其它属性、位置、角度、关系和相机操作期间的运动标记仍严格检查。
这修复了已证实的首个错误阻断，尚不代表全部取景过程已经恢复。

当前验证机制可以不取景：新增 `--view-mode none`，只读取原生状态、动作回执与位移，
不调用拍摄引入的暂停或相机操作；图片状态标为 `not_requested`，不能误报缺图。
原生机制runner默认使用该模式；第36、39步显式要求图片，行为仍由对应参数决定。

下一步只重查之前受取景干扰而无法采纳的 **F10嵌套搬运 / FloorPlan1**：
先确认内容物在内层、内层在外层，再拾取外层，比较三者位移及相对位置。
它同时验证新的原生状态入口；不重跑其它已确认条件。

同步最新代码后运行（环境沿用，不安装）：

```bash
source "$HOME/.config/thor20/server.env" &&
cd "$HOME/idea1_verify_all/idea1_firsttest_20sample" &&
bash linux_server_operation/40_verify_native_mechanism.sh
```

程序依次：相关测试 → 已有Unity缓存检查 → 一个场景的构造、干预与原生状态比较 → ZIP。
日志增加 `CHECK PASS/FAIL`、实际对象类型、搭建顺序和最后一次位移误差。
**本步骤没有图片是预期行为，ZIP小不是采集失败。** 结论看最终status及关键检查：

- 搭建成立、外层确实移动、内层与内容物位移符合判据：支持本次条件下的嵌套随动。
- 搭建成立、外层移动、随动判据未通过：查看原生轨迹中的反例。
- 搭建失败：该物品组合未完成试验，不是机制反例；不为追求全通过继续穷举。

日志中的某个失败候选可以与后续成功构造并存；最终机制判据和status决定解释。
输出仍打印 `Bundle:`，文件名仍含第31步，完整检查与状态在ZIP的result/snapshots中。

若另需验证相机修订，才单独运行已有第39步命令；它不是原生机制检查的前置条件。
Windows只做源码和静态检查，本次新增代码与测试以Linux执行结果为准。
