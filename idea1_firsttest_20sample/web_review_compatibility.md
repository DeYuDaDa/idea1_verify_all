# 网页审核 PowerShell 兼容范围

这里的处理器是 `New-WebReview.ps1`、`Update-WebReviewScenes.ps1` 以及 `一键网页审核.bat`，运行要求是 **PowerShell 7**。它们整理本地已有文件，不运行 Python、模型或模拟器，也不生产/修补图片。

## 能直接复用的格式

| 来源 | 最小目录/字段约定 | 当前支持 |
|---|---|---|
| 正式 Dataset 公开输入 | 根目录含 `data/input/*.json`；每条有 `model_input` 对象、非空 `frames` 和 `questions` 数组，图像使用相对于根目录的 `data/media/...` 路径 | 展示公开输入、原序图片和逐题审核；可选对齐 hidden_gold；与具体调用哪个模型无关 |
| 旧单视角机制日志 | `observations/attempts/<case>/<scene>/result.json`、`capture_index.json`、`actions_by_reset.json`；截图记录使用相对于 attempt 的 `rgb_path` | 支持旧 Step31；不要求曾运行模型 |
| 新多视角机制日志 | 同上；同一 capture 的 `view_frames` 是数组，各 view 的 `rgb_path` 相对于 attempt，`purpose` 描述视角用途 | 展开互补视角，保留其属于同一时点的说明；单元素数组也按数组处理 |
| 只记录状态、不拍照 | 新记录明确有 `image_requested=false` | 不计入预期图片；仍保留于底部原始记录 |
| 已有旧版嵌套重置快照 | 没有 image_requested，但运行包中 `source/nested_setup.py` 明确保存了对应 `image=False` 调用，且标签、无图片/无采集错误条件相符 | 按已核实源码识别元数据快照；不会泛化为忽略所有无路径记录 |
| ZIP | 解压后包含上述一种数据根目录 | 一键脚本可解压再处理；7Z/RAR 另需已有7-Zip；其他格式先手动解压 |

一个目录有多个候选数据根时，一键脚本要求选择，不再默选最浅的目录。`OutputRoot` 需为新目录，保护已有审核。

## 不能据此承诺支持的输入

- 任意第三方 benchmark JSON、单独预测日志、单独模型目录、只有图片而无输入/问题的目录。
- 新增事实族、新操作流程或新问题接口：文件读取得了不代表中文题意自动正确；需要对应叙述/输入适配。当前机制文字适配范围为项目 F1–F11 模板。
- 绝对 Linux 路径、越出根目录的图片路径、缺少的图片：会标明路径/文件问题，不靠猜文件名补图。
- 没生成、被原生状态保护作废、或未被原记录采纳的图片：只能显示诊断，不能通过重新导出恢复有效证据。
- 模型专属 system 消息、多轮会话、视频/音频等新模态：须增加接口适配，不能把当前多图文本草案当它们的原请求。

## 三个独立判断

1. **格式兼容**：字段能正确读取、路径能精确解释。
2. **原始证据完整**：需要的图片实际生成，文件存在，原生测量没有被运行记录判无效。
3. **题目视觉可答**：图片能看清必要状态/关系，给定文本和规则足以回答。由人工继续审核。

前一项成立不推出后一项。`media_present_not_visually_approved` 仅表示源图片文件齐全；不是已验收。`source_incomplete` 表示只生成了诊断网页。

## 本轮实际导出核对（2026-10-25）

- 旧 Step31 单视角：90 条、752 次图片引用，0 缺图，249 个复制图片文件。
- 标准 Dataset 实例：1 条公开输入、6 题、4 次图片引用，0 缺图，3 个复制图片文件。
- Step38 多视角原包：16 条；去掉13个不要求拍照的元数据记录后，有155个画面项，5个图片引用可复制、150项原生取景失败。全部16条原生测量在运行记录中无效。该结果证明适配器能读取并诊断新格式，不证明原始实验成功。

这些是对实际已有数据执行 PowerShell 导出的结果，不是 Python/Unity/模型测试。Windows 没有执行新增 Python 单元测试或模拟器；浏览器点击交互也不在本轮核验范围。

## 后续遇到缺图先看什么

`site_manifest.json.batches[*].media_quality` 分开统计：

- `generation_failed_items`：原生记录说取景失败或后续停用，没有可用来源图。
- `path_not_recorded_items`：没有路径、原因也未明确；不是自动判为文件丢失。
- `missing_files`：有具体相对路径，但磁盘上找不到，检查服务器打包/本地复制。
- `invalid_paths`：路径不符合跨机器相对路径契约。
- `invalid_captures`：有文件但其采集被记录为无效，仅保留作诊断。

`invalid_native_measurements` 独立统计原生测量失效。`image_references` 是展开后的画面项，包含失败占位；不能把它当作已经生成的图片文件数。图像数组、互补视角、时点和文件 SHA 去重是不同计数。

一键脚本遇到不完整来源会显示红色诊断提示并返回退出码2；文件仍保留供定位，不会宣称数据完整。若原始生成失败，应先定位生成端再在 Linux 重跑受影响数据，不能无差别重建网页。
