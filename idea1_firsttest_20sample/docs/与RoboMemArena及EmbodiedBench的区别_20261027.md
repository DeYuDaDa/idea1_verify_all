# 当前选择性更新试验与 RoboMemArena、EmbodiedBench 的关系

2026-10-27。结论依据官方论文及公开仓库，并核对本项目当前导出代码；未运行这两个外部基准，也未逐条检查其全部episode。当前H01–H05是待验证的受控诊断候选，不视为已完成的大型benchmark或已提出的方法。

**判断：不是相同评测协议，但场景和所需能力明显重叠。仅将行动任务改为问答，不能证明研究创新。**

## 两项工作实际让模型做什么

RoboMemArena 研究机器人记忆驱动的连续操作。其模拟任务包括转移、遮挡、计数、顺序；例如先把饼干放进某个抽屉，再把巧克力放进同一个抽屉，或记住先前放物品的位置继续操作。评测接口接收观察和任务提示，返回动作序列并执行，依据模拟器阶段条件计算任务完成与进度。参考系统PrediMem保存视觉关键帧，并结合近期观察决定子任务，再交给动作策略。它已有位置、容器与操作历史记忆，不应被说成只测静态记忆。论文和当前仓库有更新差异，本文不声称核对了所有版本的任务。

来源：[RoboMemArena论文](https://arxiv.org/html/2605.10921)、[官方任务定义](https://github.com/OpenHelix-Team/RoboMemArena/tree/main/bddl)、[官方评测接口](https://github.com/OpenHelix-Team/RoboMemArena/blob/main/evaluation_benchmark/README.md)。

EmbodiedBench 研究MLLM驱动的具身任务执行，包含EB-ALFRED、EB-Habitat、EB-Navigation、EB-Manipulation。与我们最接近的是使用AI2-THOR的EB-ALFRED：已有取放、加热、冷却、清洁、切片等任务。其MLLM规划器接收图像、任务及配置决定的历史/反馈，输出可执行行动计划，可以总结历史与反思重规划。任务/子目标评分检查终态目标是否成立。它显然已涉及变化的世界状态，不能以“我们研究动态状态”为区别。

来源：[EmbodiedBench论文](https://arxiv.org/html/2502.09560)、[官方仓库](https://github.com/EmbodiedBench/EmbodiedBench)、[实际规划器代码](https://github.com/EmbodiedBench/EmbodiedBench/blob/master/embodiedbench/planner/vlm_planner.py)。

## 与我们当前实现的对照

| 对照项 | 两项已有评测 | 我们当前实现 |
| --- | --- | --- |
| 场景 | 物品取放、容器关系、历史操作；EmbodiedBench另有加热冷却等 | 多数物理操作有重合，不构成独立创新 |
| 模型任务 | 在线产生行动并继续执行 | 接收预录第一人称历史，回答指定事件后的事实 |
| 主要评分 | 任务、阶段或子目标完成 | 逐事实判断变化和保持；当前仍是答案，不是内存写入记录 |
| 对照结构 | 任务包含记忆需求，但核查的协议未设置我们的范围诊断四格 | 尝试固定最后事件、改变当前作用关系，同时问正负后果 |
| 研究角色 | 完整具身系统的执行评测 | 方法开发前的受控诊断，可与已有执行任务互补 |

当前 `hard_export.py` 只导出V与S：V是视觉历史加统一规则；S是准确事件前状态加准确目标事件。V/S同时改变感知、历史恢复和事实表达，不能单独隔离所有错误来源。原设计另有分阶段诊断，但不能把尚未实现或尚未测得的结果写成已经完成。

## 最能体现区别的具体例子

初态P外盘承载B碗，B承载X苹果。四题最后都拿起同一外盘P；历史决定当前承载关系。

| 当前关系 | 拿P后P移动 | B移动 | X移动 |
| --- | --- | --- | --- |
| X仍在B里，B仍在P上 | 是 | 是 | 是 |
| X已取出，B仍在P上 | 是 | 是 | 否 |
| B连同X已移到外面 | 是 | 否 | 否 |
| B已移走，X改为直接放在P上 | 是 | 否 | 是 |

这是**设计预期表**，只有原生构造、关系和位移核对通过后才成为对应实例的标准答案。此前H04-2、H04-3形成候选，不能据此声称H04-1、H04-4均已完成。

差别应落在这组相互约束的判断：不仅记住苹果在哪里，还要在同一最后事件下区分直接变化、有效连带变化和不应变化的事实；关系断开时停止推导，改接后又能恢复正确推导。在本轮查到的两项评测协议中，未找到同样的配对事实评分设计。但这只是针对这两项工作的有限核查，不是全领域空白证明。

## 不能越过的结论边界

1. “机器人操作会改变世界，模型需要记忆变化”已经被研究；模拟器、热状态或问答形式都不能单独当创新。
2. 最终问答错误只能先称为当前状态/后果判断错误。若没有审计方法实际维护的记忆，不能说它在内部写多了或写少了。派生事实能够在查询时正确推出即可，不要求每条都显式写入。
3. H01交错记忆、H02身份交换、H05加热冷却与既有能力要求重合较多，适合提供控制和扩展。H04的关系切断/改接与正负后果配对更能支撑范围诊断，但仍需实测失败和方法收益。
4. 我们的QA分数不能直接与他们的任务成功率比较。他们任务失败也不能直接作为影响范围失败的证据。

建议维持小规模诊断，不扩展成另一个通用机器人记忆benchmark。方法应在这些受控条件下证明改变了哪类错误；下游价值再用EmbodiedBench一类已有任务验证。当前可支持的是评测目的不同，尚不支持新方法已成立或科学问题已被实验证明。
