# H01 视觉状态历史工作规范

此技能归档的是 H01-1 的具体经验，供处理同类 THOR 历史序列时参考。它保存在仓库归档目录中，不会因此被安装、注册或启用。它不是 AI2-THOR 的通用接口手册，也不表示每个房间、资产或后续变体已经验证。详细失败包、源码位置和证据边界见[证据与失败记录](references/evidence-and-failure-history.md)。

## 执行边界

- Windows checkout 只用于查看、编辑和静态检查；需要真实动作、图像或 Unity 结果时，由用户在服务器执行已记录的步骤。不得据静态代码、mock、设计表或历史成功包声称当前服务器结果通过。
- 开始改动前，按运行时实际 Unity/AI2-THOR commit 阅读对应原生 action 重载、字段语义及其调用链。不要把名称相似的重载当成同一种操作。
- 将私有库存准备、可行性校准与正式公开历史分开标记。校准取放、试接触、恢复动作不能计入公开叙事；进入公开历史前重新核对初态。
- 每个节点记录计划、原生回执、真实状态、图片引用和状态（通过、失败、未执行）。关键节点失败后停止后续历史，保留首错和诊断，不把题目包装成完整样本。
- 对每个构造结果分别评估原生测量、图片文件完整性、视觉可答性和人工接受状态。程序状态通过不等于画面可读；ZIP 存在或候选生成成功也不等于样本通过审核。

## 关键操作与状态判定

- **相对旋转与扶正：** 先确认所用 `RotateHeldObject` 原生签名。此处已查实的构建中，`pitch/yaw/roll` 浮点重载施加相对旋转增量，`Vector3 rotation` 重载是绝对姿态设置。对相对增量，保存每个成功执行的增量；恢复时按相反顺序逐项施加其逆增量，并检查实际姿态、手持身份和物体状态。不能把逐次增加的目标角误当作绝对角，也不能用 `roll=0` 代表归零。
- **自然接触与直接改状态：** 若研究问题声称真实接水、倒水或接触机制，必须走对应物体接触及原生状态变化路径，并分别保存前态、动作、后态。不得用 `FillObjectWithLiquid` 或 `EmptyLiquidFromObject` 兜底后再称为自然交互。直接 setter 可以用于明确标记的私有初始化，但不能混入正式历史证据。
- **可见与可达：** 物体在画面中可见、可导航到附近，不证明手或手持物可到达目标。检查原生可达站位、实际手持物中心到目标的距离、碰撞返回和移动后的状态；失败要指出究竟停在几何预检还是原生动作阶段。
- **容器关系：** `parentReceptacles` 中出现祖先台面，不证明杯子已从咖啡机取出。恢复应双向核对直接停放容器与 `receptacleObjectIds`，确认目标机器不再关联杯子，且杯子未被持有。
- **目标事件：** 保存实际目标动作的即时回执和前后 metadata；不能用后续 `Pass` 成功替代目标 `PutObject` 成功，也不能仅凭预期终态生成标准答案。观察窗口应事先确定，不能因目标变化未出现而不断延长。

## 身份、历史与证据

- 对外观相同的杯子，用正式历史首次拿取顺序建立身份，并把本题命名规则写进公开输入。H01-1/4为先A后B，H01-2/3为先B后A；不能把“先拿的一律是A”当普适规则。后续重复拿取沿用身份，私有校准不参与命名。每次首次正式取拿都要与固定objectId绑定，并让审核者从真实画面核验连续追踪。
- 每个状态变化都同时检查目标杯变化、另一杯应保留的事实、位置/承载关系、机器状态和手持 inventory。对改变与保留分别留证，不能只检查最终答案。
- 图片是否存在及其来源，须与语义可读性分开审核。杯子/液面是否清楚、身份是否可追踪、动作是否足以支持问题，需要人工检查；私有 metadata、objectId、检查点答案或后续追踪不能偷偷补入模型输入。
- 逐步压缩（RLE）只能在精确像素重复且连续步骤、相同阶段和同步视角组满足条件时合并。保留每个原生步骤到图像路径/像素哈希的映射，包括检查点引用；不得逐个视角独立合并而破坏同步。debug 未采样步骤没有图像证据，不能宣称视觉连续。
- 已通过数据保持原包、SHA-256 和人工接受记录。新的变体或改动后的生成器结果是独立候选；旧样本通过状态不自动扩散给未审核变体。若来源、图像或历史改变，按新版本重新审核。

## 校准与参数边界

先做区分力最高的单变体、小范围原生核验，再决定是否扩大。候选位置、移动步长、角度、等待次数和搜索上限都是该场景/构建的操作预算，不是模拟器普适限制。历史中出现的 0.85 米、20 度、4 厘米、五个候选仅可作为该次实现的参数背景；新任务需从对应构建、场景几何与实际回执重新确定，不得机械复制或写成原生接口上限。

异常恢复按所处阶段限定：仅可在错误确实属于接水几何试探、杯仍在手且仍为空等已验证前提成立时恢复几何候选；倾倒或扶正阶段的失败应原样停止，不得回到接水搜索、传送或重置现场。参考文档中记录的任何修复，在新的执行包出现前都只是实现变更，不代表已由模拟器验证。
