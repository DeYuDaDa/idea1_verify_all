# 首轮 20 组事实影响范围诊断

本目录是实验代码，不是已经生成的数据集。设计为 20 组 A/B 配对、40 条场景记录。2026-10-18 最新服务器日志确认：依赖安装和 18 项单元测试通过，Vulkan loader 已安装且可加载；目前失败在 NVIDIA Vulkan 设备枚举，尚未启动模拟器或生成数据。Windows 端不运行 Python、测试、模拟器或安装环境。

## 路径约定

| 用途 | Windows | Linux 服务器 |
|---|---|---|
| Git 根目录 | `主线1/idea1_verify_all` | `/root/idea1_verify_all` |

| Git 外材料与输出 | `主线1/will_not_be_push_to_git` | `/root/will_not_be_push_to_git` |

服务器默认将生成结果写入 Git 外目录中的 `idea1_firsttest_20sample/exports`；环境报告、日志、模拟器试启动图像也在 Git 外目录。当前没有需要用户从 Windows 私有目录手工复制的必需材料。

## 现在先做什么

同步代码后，按 [首轮服务器命令](linux_server_operation/00_start_here.md) 执行前四步。命令、可选参数、后续生成和打包操作全部放在 `linux_server_operation/`。本 README 不要求在 Windows 执行任何项目命令。

第 11 步已找到明确缺失：NVIDIA 初始化时动态加载 `libEGL.so.1`，各系统路径均返回 ENOENT。已有该结果的服务器直接按 [第 12 步 EGL 修复](linux_server_operation/12_egl_repair.md) 操作，安装提供该文件的 `libegl1` 及必需依赖，确认 NVIDIA 枚举成功后再试启动。复用现有 Conda 环境，不重跑前面的安装、测试与诊断。

首轮顺序是环境检查、独立 Conda 环境、单元测试、模拟器试启动。成功后再运行六组试生成；不要先启动全部 40 条。任何一步失败都先保留该阶段日志，不需要继续执行后续阶段。

## 生成成功不等于数据已经验收

每次尝试会保存原生动作结果和实际前后状态；不将设计中的 Expected Update 当成 Gold。两个版本均完成，且预定机制的实际差异得到核验后，才发布为候选配对。失败尝试保留在 Git 外输出的 `_attempts` 目录。

候选仍需检查画面可见性、条件是否仅在计划范围内不同、提供的历史事实和规则是否足以支持查询。默认不把它们标为完整审核通过。S07、C15 的事件目标/放置目标不同，按非严格最小配对分析；M03 检查不同初始脏污值的保持，不假称它有变化/不变标签翻转。

试启动以后的试生成、证据审阅、六组子集打包和全量命令见 [后续服务器操作](linux_server_operation/08_after_smoke.md)。审核不会修改实际状态标签，也不能覆盖模拟器校验失败。

若某机制或物品组合无法原生构造，生成器会留下失败记录，不能用补造元数据、人工修改结果或替代图片凑齐 40 条。

## 输入协议与泄漏边界

第一版采用“已知历史事实＋明确设备规则＋视觉事件/成功动作记录”的受控条件，定位选择性修订，而不声称模型自主从视觉发现了全部关系和规则。

- `data/input`：模型可见的历史事实、规则、事件说明、问题和 RGB 路径。
- `data/media`：模型可见 RGB。实例分割与全场景元数据不混入公开输入包。
- `hidden_gold`：实际前后状态、事实差异、直接/间接分类、可知性、评测目标等。
- `private_logs`、`pair_receipts`、`_attempts`：生成证据、候选收据和失败审计。

间接事实无需被额外物化才能算正确。位置查询只问是否发生位移；包含查询使用已提供的对象别名，不要求 VLM 凭普通 RGB 精确回归隐藏的三维坐标。C14 已装水杯的温度不能仅靠咖啡填充规则确定，保留为不可确定查询，不用隐藏温度强行评分。

## 离线运行边界

图像、历史、规则、问题和隐藏评分结果导出后，VLM 可在另一平台离线回答，无需 AI2-THOR。公开打包时移除 A/B 文件名提示和原生事实 ID，私有映射留在评分目录。

模型若需要实时选择动作并观察执行结果，才需模拟器在线；当前构造流程不提供该交互评测。当前也未运行任何模型，不预判会出现 under/over-propagation。

## 尚未由服务器验证的风险

Linux/NVIDIA/Vulkan、Unity 构建下载、具体房间的物品组合、容器容量、流水接触区域、热量/烹饪时序和相机视野都需要真实运行。代码保留动作成功与实际状态双重检查，无法用静态审阅替代物理验证。

`--resume` 仅复用代码指纹匹配的完整候选。代码改变后应使用新的 Git 外输出目录保留旧证据，不在旧数据上悄悄改标签。没有自动提交或推送 Git。
